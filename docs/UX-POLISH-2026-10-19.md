## Changes

- Shared amber bolt artwork for the tray, Desk title bar, taskbar and application header. The Windows
  MSVC executable embeds 16–256 px icons; the installed shortcut explicitly selects that icon. The
  running Desk sets the same app identity as its shortcut.
- A consistent light/dark palette, readable secondary text, 14 px body text, 22 px page headings,
  32 px controls, and shared margins and spacing.
- Brand/connection status and navigation have separate rows. Inbox cards have a clear selected state,
  wrapping titles, and accessible question/batch labels. Paging controls appear only when needed.
- Question details distinguish the answer area from source information. Immediate-send choices are
  explained, forms fit narrow panes, and text/form submission has a clear primary button.
- Agents and Owners use readable cards instead of wide tables. Settings has separate Notifications,
  Phone replies and Owners sections with independent scroll positions. Phone fields align and setup
  guidance is expandable.
- Consistent page headings, improved empty/offline states, Enter-to-search in directories and History,
  and a clear search-reset action for agent/owner directories.

## Local keyword and message search

Artem asked to find the right chat by keywords, then explicitly chose to include chat messages searched
locally. Sessions now presents a ranked result list while searching, including older matches without
opening the Recent chats disclosure. Clearing the query returns to the grouped browsing view. Result
cards retain their activity label and direct Open chat or Resume in a terminal action.

Title/project ranking accepts words in any order, partial words and bounded spelling corrections.
Quotes require a phrase and minus-prefixed terms exclude matches. Message matches use local full-text
word/prefix matching, with a short excerpt. Metadata matches lead, followed by full-text relevance.
Ranking, discovery and incremental message indexing run on the separate session worker, with a typing
debounce and old-query results hidden. Message progress and incomplete-coverage notes distinguish an
unfinished or bounded search from a definitive empty result.

Codex's visible user/assistant message items and Claude's user/assistant text blocks populate an
in-memory SQLite full-text index. SQLite temporary storage is also memory-only. No queries or extra
message copies are persisted or uploaded. Reasoning, tool payloads, attachment content and credential
files are excluded. Validated Claude transcript IDs can surface older local chats absent from the live
registry; without a verified Desktop destination, these offer terminal resume. Provider paths remain
local and cannot follow links or transcript-supplied file references. [Search scope and bounds](SESSIONS.md)
document the supported providers, message limits and live-refresh interval.

## Sessions respects the warm Desk activity gate (2026-10-23)

A source audit after packaging `85c66d2` found a second `poll(true)` call inside the Sessions renderer.
It bypassed the application's focused/visible/not-minimized gate whenever an inactive warm window
rendered. With a nonempty search, this could continue provider discovery and message indexing.
Pending-index repaints and spinners could also keep requesting frames after activity stopped.

The app's gated logic call is now the only entry point that schedules session work. Rendering only
uses cached results. A completed in-flight batch can be collected while inactive, without scheduling
another. A refresh request survives an in-flight batch and forces fresh metadata on re-entry. Manual
Refresh and Clear request a new frame without making the page active. Progress repaints require an
active page and a nonempty query; spinners and running-card animations also honor that activity state.

This is a source-level fix for a concrete bypass. It does not establish the required idle CPU threshold
or warm opening times; those measurements and all automated/live tests remain paused.
